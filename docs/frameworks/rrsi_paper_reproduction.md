## 论文主张与 coding 结果

论文研究的重点是：在冻结模型权重时，对 Harness 的候选提案与接纳施加约束，使演化结果能够迁移到搜索时未使用的任务；并非保证每个候选、每一轮都涨分。更新幅度、历史反馈、结构探索、泄漏审核、噪声容忍、成本约束与剪枝共同控制搜索。出处：[论文](https://arxiv.org/html/2609.24972v1)。

| 冻结执行模型 | 测量任务 | 原始 | RRSI | 差值 |
|---|---|---:|---:|---:|
| Claude Opus 4.8 | Terminal-Bench 2.1，搜索环境 | 74.2% | 80.2% | +6.0 个百分点 |
| Claude Opus 4.8 | SWE-bench Verified，迁移测试 | 82.0% | 83.8% | +1.8 个百分点 |

数据为论文表 3 报告值，尚未在本机复现。先以 Claude coding 路线为复现目标，避免将不同模型实验的执行者与改进者配置混在一起。论文中相对未正则化演化的 token 节约，也不能解释为最终 Harness 一定比原始 H₀ 更省 token。

## 与已做实验的差异

以下原设置来自已锁定的 [官方 coding 配置](../../repos/rrsi/domains/coding/rrsi.json) 和 [官方说明](../../repos/rrsi/domains/coding/README.md)，对应 [作者仓库](https://github.com/google-research/rrsi)。

| 项目 | 官方 Claude coding 设置 | 我们已跑的适配实验 |
|---|---|---|
| 执行模型 | Claude Opus 4.8，冻结 | DeepSeek Flash，thinking 关闭 |
| 搜索角色 | Claude Opus 4.8 | DeepSeek Flash |
| 起始 Harness | Harbor 的 Terminus-2 副本 | mini-SWE-agent 2.4.6 |
| 搜索任务 | 全部 89 道 Terminal-Bench 2.1 | 全部 50 道 Verified Mini |

| 搜索轮数 T | 20 | 1 |
| 每轮候选数 m | 2 | 1 |
| 每题每次评测重复 k | 2 | 1 |
| 原子编辑预算 | 从最多 4 项向 1 项退火 | 固定 1 项 |
| 噪声 δ | 配置 0.017，另见下文公开轨迹差异 | 固定 0，没有校准 |
| 带内选择权重 | w_s=0、w_c=15、w_n=0.5 | w_s=100、w_c=0、w_n=0 |

不是把 T 从 1 改成 20 就自动构成论文复现。模型、起始 Harness、任务、运行预算、采样与重试、评测版本和选择配置都需要对齐；运行后不能根据迁移测试结果再调搜索规则。

## 分两种复现，按阶段推进

**A. 已发布产物的效果复核。** 对齐模型和评测条件，使用作者 H₀ 和已发布 champion，在同一时间窗口分别重新评测。先做少量工程任务 smoke，再完成 Terminal 89×2；配置核清后，再进行 SWE500 的双臂评测。该路线检验已有 Harness 能否带来收益，不能证明我们独立重现了搜索过程。

**B. 搜索过程重跑。** 从官方 H₀ 开始，使用原模型、原生提案／选择规则和完整 20 轮搜索，生成我们自己的候选与最终版本，再做未反馈给搜索的迁移评测。该路线回答我们能否重新找到有效 Harness；还需独立重复来评估稳定性。

优先 A，再 B。这样可以先区分产物本身、运行环境和搜索过程三个问题，避免一次同时更换多个变量。若只能继续使用 DeepSeek，则可研究 RRSI 的模型迁移，但应标为新模型适配，不能以论文 Claude 的数字作为必须达到的指标。

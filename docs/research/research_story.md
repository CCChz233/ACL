# 面向 Harness 自改进的证据高效上下文

更新：2026-10-20。**本文是当前唯一的故事定义。** 本次根据相关工作核验，将主线深化为“修改决策的证据需求与获取策略”；详细实验设计见 [深化方案](evidence_research_agenda.md)。研究计划见 [research_plan.md](research_plan.md)，执行清单见 [next_steps.md](next_steps.md)，对照协议见 [harness_baselines.md](harness_baselines.md)。旧主线已退出当前待办，存于 [归档](../archive/2026-10-19-before-context-story/README.md)。

基础故事来源：[用户提供的原文](../../references/notes/research-story-input-2026-10-19.txt)；2026-10-20 的深化依据为随后关于相关工作、证据需求和成本的讨论。

暂定题目：**What Evidence Does Harness Self-Improvement Need?**。

## 1. 核心故事

Harness 自改进的优化器需要反复阅读执行轨迹、Harness 源码和历代修改结果。随着优化推进，历史越来越长，同一段代码、重复失败和无关工具输出可能反复进入模型输入；但简单删减也可能抹去失败归因和回归判断所必需的证据。

我们研究：**在固定模型和 Harness RSI 核心协议下，哪些证据、以什么粒度、在什么决策时点影响修改结果？能否根据这些需求获取证据，以更低的完整成本产生同等或更好的 Harness？**

先在相同历史快照上进行证据移除、补回和粒度干预，检验其对实际候选的作用，再设计读取策略。已有 **Edit-Aware Evolution Context（EAEC）** 仅作为待验证实现代号：可追溯索引、决策条件化证据和按需展开都已有相关先例，不单独作为新意。比较时固定 RSI 算法、优化模型、任务执行模型、初始 Harness、编辑空间、反馈权限、验证与接纳规则；改变的是优化器的上下文呈现和读取策略。

这是一项 **Efficient Harness Self-Improvement** 研究。成功标准是更好的成本—改进质量关系，而不只是摘要更短。当前尚无 EAEC 的实现和效果证据，以下均为待检验设计。

新的证据链为：**优化成本与版本审计 → 证据移除/补回及粒度实验 → 固定读取策略与强对照 → 完整多轮 RSI → 跨框架与独立任务验证。** 不以阅读频次或模型自述代替证据作用；不声称证明了全局最小充分证据集。

## 2. 研究问题与边界

| 问题 | 需要的证据 |
|---|---|
| RQ1：成本主要花在哪里，哪些读取是重复的？ | 原始请求级账本；轨迹、源码、修改历史与工具输出的读取分布和重复率 |
| RQ2：有效修改真正需要哪些信息？ | 在相同历史快照上消融失败位置、前后状态、源码锚点、修改历史与成功反例，观察真实后续候选 |
| RQ3：面向修改决策的组织是否优于通用摘要和检索？ | 同一算法内的上下文方法对照，完整计入组织成本，比较候选质量与独立 Resolve Rate |
| RQ4：效果是否跨轮次、框架和未见任务成立？ | 冻结策略后，在独立确认数据及多个框架中比较成本—性能曲线 |

主线不再是模型自改进能力排名、D/P/I/V 跨模型替换或向 Qwen 定向蒸馏。首轮不训练模型权重，也不以创造新的 RSI 搜索算法为目标。诊断与消融用于解释证据组织机制，不能自动被解释成模型内部能力分解。

这里优化的是 **Harness 优化器的上下文**，不是主要压缩 task Agent 解题时的上下文。后续候选可以按原框架合法范围修改任务 Harness，但所有组共用相同范围。若同时改变 task Agent 的预算或上下文机制，必须单列实验。

## 3. 相关工作与创新边界

以下文献名称与核心机制已按论文页面/官方仓库核对；效果数字属于各论文原设置，不是本项目成绩。

| 工作 | 在本研究中的位置 | 需要区别的地方 |
|---|---|---|
| [ContextEvolve](https://arxiv.org/abs/2602.02597) | 最直接的方法基础与强对照；用 Summarizer、Navigator、Sampler 组织系统代码优化上下文 | 不能把“摘要＋方向总结＋历史采样”本身作为新意；需要检验 Harness 修改决策中的必要证据及跨框架收益 |
| [Meta-Harness](https://arxiv.org/abs/2603.28052) | 核心 RSI 验证框架；允许通过文件系统访问历代源码、得分和轨迹 | Full Context 应保留其原生信息访问能力，不能故意削弱成不合理的单次超长拼接 |
| [CIG](https://arxiv.org/html/2610.05039v1) | 必须纳入的直接相关工作；持久组织证据、假设、干预和结果，包含结构消融及同 proposer token 预算比较 | 结构化关系与同预算更高质量已有先例；context-only 适配与原生图驱动规划/选择必须分开 |
| [MCE](https://proceedings.mlr.press/v306/ye26g.html) | 上下文工程技能与上下文产物共同进化 | 不把“上下文组织自动进化”当作无人研究的后续创新 |
| [HarnessFix](https://arxiv.org/abs/2606.06324) | 第一套实验系统与结构化诊断参照；HTIR 联系执行步骤、实现锚点和修复过程 | HTIR、失败到源码映射、定向修复已有先例；不能换名后宣称原创 |
| [ACON](https://arxiv.org/abs/2510.00615) | 基于失败反馈优化压缩准则的重要强对照 | 原文含自然语言准则优化及可选蒸馏；移植版本要披露学习成本，不能把学习式压缩当作普通静态摘要 |
| [Evo-Harness](https://arxiv.org/abs/2608.15071) | 从执行上下文提炼可复用 Skills 的相邻工作 | 我们聚焦修改优化器所需的证据组织，不泛化为执行经验提炼或在线技能学习 |

[HarnessFix 官方仓库](https://github.com/HarnessFix/HarnessFix) 提供 SWE 管线和内嵌 mini-swe-agent；本地已克隆、固定版本。它与 Meta-Harness-adapted 均已完成离线检查及含显式恢复的两题真实闭环，候选分别 1/2、0/2，原始基线 1/2，均保留 H0。这是工程证据，非正式上下文实验，详见 [真实验收](../frameworks/framework_live_pilot.md) 与 [接入边界](../frameworks/framework_integration.md)。DeepSeek / Agent 版本、工具和恢复差异单独记录，不称作原论文数值复现。

ContextEvolve 在 ADRS 原设置报告约 29% token 降低；这只说明相关方向已有直接方法基础，不作为我们的预期收益。[论文](https://arxiv.org/abs/2602.02597)

HarnessFix 论文的 SWE 行报告 48.9M 离线进化/修复 token，默认使用 GPT-5 mini。该数值是成本审计线索，不能当作 DeepSeek 的默认预算、我们的消耗或可直接复现的目标；还需对齐其统计范围和运行规模。[原文表 IV 及实验设置](https://arxiv.org/html/2606.06324v2)

## 4. 方法假设：Edit-Aware Evolution Context

### 4.1 从原始历史到可追溯证据

原始轨迹和源码保留不变。先建立只覆盖允许反馈历史的索引，记录运行、候选、父版本、步骤与源码版本标识，再把以下信息组织成证据单元：

- 当前失败及其前置状态、关键动作、观察和直接后果；不能只截一个错误字符串。
- 负责该行为的 Harness 文件、组件、源码片段及版本锚点。
- 历史修改的 diff、允许公开的验证结果、接纳或回滚理由。
- 重复失败的合并引用，以及反驳当前诊断的成功案例与回归证据。
- 原始证据地址、截断范围、不确定性和无法归因之处。

上述单元形式只是候选设计，不把构建结构化记录本身当作贡献；尤其不能重新命名 HarnessFix 的 HTIR。

### 4.2 按当前修改问题生成证据视图

输入为当前候选/组件、待检验问题、合法编辑范围、历史截止点和剩余上下文预算。提供与本次决策有关的证据，而不是每次返回固定摘要。当前假设、问题分解和查询规划若由额外模型产生，调用也计费；不得把完整修复方案隐藏在“检索查询”中免费提供。

证据不足或出现冲突时，优化器可以展开原始步骤、相邻窗口、源码或历史修改。展开沿用原框架的信息权限和工具约束；索引不能替模型获得隐藏测试、参考补丁或事后结果。

### 4.3 需要验证的机制

目标是检验“修改问题条件化的证据选择＋可追溯按需展开”能否形成更好的成本—质量关系。至少消融：不按修改问题条件化、无源码锚点、无历史修改结果、无成功/回归反例、无按需展开、仅普通检索。若效果完全由普通摘要或缩短输入解释，应收窄贡献。

## 5. 不变部分与允许适配

| 固定项 | 具体要求 |
|---|---|
| RSI 核心 | 同一框架内固定父候选选择、提案/修复流程、必要诊断阶段、候选评测、接纳/回滚与停止规则 |
| 模型 | 优化器与执行器固定 `deepseek-flash`，推理配置一致；组织器默认同一模型，额外调用独立计账 |
| 目标 Agent | 保留 mini-SWE-agent；HarnessFix 内嵌版本与现有 2.4.6 如不同，先审计再冻结，不覆盖原 Agent 或悄悄换版本 |
| 任务执行 | 相同工具、容器、任务版本、每题调用/token/时间上限和独立评分 |
| 反馈权限 | 相同历史截止点、可见任务与源码；候选生成期间不读取未来候选结果 |
| 唯一主变量 | 优化器看到的证据组织、默认视图、检索与展开策略 |

HarnessFix 的必要 HTIR、诊断或验证若被跳过，就不是“同算法只换上下文”的主比较。原流程中保留的成本必须计入；若要改动这些阶段，另列扩展，明确归因范围。框架间比较以各框架内部的收益为主，不把异构搜索过程硬说成完全相同算法。

## 6. 两类 Baseline 分开

**Context Baseline 是直接方法对照。** 第一阶段先做原生访问下的证据干预；策略比较包含 Full Context、LLM Summary、Retrieval-based、EAEC，并补齐 Truncation、ContextEvolve-adapted、CIG-inspired context 与 ACON-adapted。正式方法结论不能只依赖弱摘要对照。CIG 原生系统涉及搜索流程变化，另列系统级比较。移植方法保留关键机制、匹配信息权限并记录适配差异，不冒充原生论文实现。详细定义见 [对照协议](harness_baselines.md)。

**RSI Framework 是泛化轴。** HarnessFix 为首个实验系统，Meta-Harness 为第二个核心验证框架（均 P0）；GEPA 和 RRSI 为 P1 扩展；DGM、Harness² 暂列 P2。不是先把所有框架都跑一遍再宣布新方法有效。

补充状态：DGM 已完成适配及真实评分；最新高预算两轮原始候选为 6/10、3/10，见 [最终汇总](../../experiments/runs/full10-highbudget-completion-v1/report.md)。其作为开放式谱系搜索扩展，不改变上述主线的验证顺序，也不替代直接上下文方法对照。

## 7. 首轮实验：共享轨迹、相同快照

先冻结同一父 Harness、允许历史、源码版本和评分反馈。证据原生可访问、移除、补回等条件从同一快照的独立会话出发，使用相同优化模型生成候选，再通过相同执行与评分过程检验；有局部信号后再做策略比较。多个快照使用配对设计，不让某组先看到其他组生成的候选或结果。消融须同步限制工具中的旁路访问；若前序对话已经包含被移除证据，须从污染之前重启。

这一步检验表示/访问层的局部效果，不等于完整多轮 RSI。等有稳定信号后，再恢复各框架的完整搜索与历史增长过程，报告多轮累计成本和最终独立性能。

必须覆盖失败历史、成功历史和回归场景。人工根据未来结果挑选的“关键证据”只能作为回顾性分析，不能混入可部署策略。允许证据来自开发数据；原始 SWE Mini50 已多次用于开发和方法选择，**不能重新包装为未见测试集**。独立测试划分及仓库/任务近重复审计须在确认实验前完成。

## 8. 指标与成本口径

四个首要指标：优化器实际 token、上下文处理额外成本、有效 Harness 修改率、独立测试 Resolve Rate。

| 指标 | 定义/注意事项 |
|---|---|
| 优化器 token | 实际输入＋输出，含所有必需优化阶段、重读和失败请求；另列输入中证据读取的估计占比 |
| 上下文额外成本 | 摘要、索引/准则生成、查询规划、检索与展开的额外模型调用、token、CPU/存储和时间 |
| 搜索总 token | 优化器和上下文处理的互斥请求集合之和；同一请求只计一次 |
| 有效修改率 | 生成候选中，合法、可执行且满足预注册开发收益及回归规则的比例；无效/无操作候选仍计成本 |
| 独立 Resolve Rate | 候选提名后在未参与方法设计和选择的任务上评分，同时报告相对 H₀ 的配对增益 |
| 效率曲线 | 同等质量的净成本降低、同等预算的性能及成本—性能 Pareto；不能只报压缩率 |

总实验成本还包含历史采集、开发评测、选择/回归评测和最终测试。共享历史同时报告一次性与摊销成本，不能把离线摘要或失败重试视为免费。缓存命中仍记录 API 实际输入 token，并把原始 token、缓存计费和真实费用分开；预算预留 token 不是实际用量。

“保持效果”需预先定义可接受退化界限与不确定性判断，不能把“不显著”当作等效。正式结果同时报告：固定候选/评测预算，以及固定包含上下文处理的总 token 预算。具体阈值、种子、轮数和费用上限在成本审计后冻结，本文件不自动扩展旧运行预算。

固定总 token 比较的搜索阶段包含组织器、优化器与开发/选择任务执行；共享历史采集和最终封存测试对各组保持一致并单独报告。仅匹配优化模型 token 的补充实验不可冒充全系统等预算。失败请求缺 usage 时记未知及预留，不当作无成本。

## 9. 实施阶段

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| P0：HarnessFix 成本审计 | 固定版本、DeepSeek/mini 适配差异、一次闭环及请求级成本分解 | 原生流程与数据边界可信，可在相同快照恢复 |
| P1：固定历史证据干预 | 原生/移除/补回与粒度条件的候选、净成本和质量 | 观察到的差异不能只由工程错误、污染或随机性解释 |
| P2：读取策略与完整 RSI | 普通摘要/检索、ContextEvolve/CIG 上下文/ACON 适配，多轮与双预算结果 | 组织器成本计入后仍有可复现的成本—质量优势或明确失效边界 |
| P3：跨框架与独立确认 | Meta-Harness 核心确认，GEPA/RRSI 扩展；独立任务验证 | 策略冻结，区分局部效果与真正跨框架通用性 |

## 10. 已有资产与当前事实

已有 SWE Mini50 原始基线 31/50、RRSI 候选 29/50、GEPA 候选 25/50，均为旧工程先导；它们验证了运行链路，并提供可审计轨迹，但不是新的上下文方法对照，也不证明性能下降由冗余或压缩引起。[实验索引](../../experiments/README.md)

可复用：DeepSeek Flash、mini、官方 SWE 评分、完整请求/响应和账本、本地 50 个永久缓存镜像、目录结构，以及经恢复跑通的 HarnessFix / Meta-Harness 最小闭环、公开快照和文件读取接口。仍缺：无人值守恢复与预算结束策略的正式验收、完整成本标注、正式共享快照与独立 split、EAEC 与强对照实现。

截至 2026-10-20，五框架高预算两轮已完成，共 100 份候选逐题评分；这些仍是工程探索，不是上下文干预对照，不能据分数归因证据组织。[最新结果与用量](../../experiments/runs/full10-highbudget-completion-v1/report.md)

同轮审计找到一次晚期编辑破坏提交协议的案例，但没有证明中间 Harness 自由运行的成绩先升后降；该案例作为运行检查与诊断材料，不把“防止改坏/何时停止”另立主线。[审计](../../reports/exports/within-round-audit-2026-10-20/findings.md)

下一步是相关工作机制对齐、快照与成本审计，再制定小规模证据干预；具体清单以 [next_steps.md](next_steps.md) 为准。旧两题闭环记录继续保留，不与新方法效果混为一谈。

## 11. 预期贡献

1. 通过受控移除、补回和粒度实验，分析不同证据对修改决策及真实候选质量的条件作用，而非从阅读频次推断必要性。
2. 根据观察到的证据需求设计读取策略，并与原生自主访问、普通摘要/检索及相关强方法比较；不把常见组件组合本身当作贡献。
3. 在完整成本口径、独立数据和多个 RSI 框架中，验证能否减少优化成本并保持或改善 Harness 质量，明确失效条件。

以上是待验证贡献；只在 HarnessFix 上改几处代码、报告更短输入或单次涨分，都不足以支持本故事。

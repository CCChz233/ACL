# 上下文对照与跨框架验证协议

更新：2026-10-20。本文覆盖旧 B0–B4 / D/P/I/V 主协议，与 [研究故事](research_story.md) 及 [深化设计](evidence_research_agenda.md) 一致。**上下文方法是主变量，RSI 框架是泛化轴，两者分开设计。** 以下均为待实施定义，不能把旧框架分数标记为这些组的成绩。

## 1. Context Baseline

| ID | 方法 | 操作定义 | 阶段 |
|---|---|---|---|
| C0 | Full Context | 保留框架原生的完整信息访问机制、必要结构及工具；不是强行一次拼接全部历史 | 第一轮 |
| C1 | Truncation | 固定窗口/最近记录或固定 token 长度；规则、顺序与长度在开发集冻结 | 补齐对照 |
| C2 | LLM Summary | 用同一冻结模型生成通用摘要，再由原优化器修改 Harness；摘要构建/更新均计成本 | 第一轮 |
| C3 | Retrieval-based | 用冻结的检索方法选择历史及源码片段；记录检索器、查询、top-k 与输出预算 | 第一轮 |
| C4 | ContextEvolve-adapted | 保留状态摘要、方向总结、历史样例选择三个关键角色，适配 Harness 优化输入 | 强对照 |
| C5 | ACON-adapted | 用失败反馈优化上下文压缩准则，适配优化器读取场景；准则学习及可选蒸馏资源单列 | 强对照 |
| C6 | EAEC（待实现） | 基于当前修改问题组织可追溯证据，连接状态/源码/修改历史与反例，支持按需展开 | 第一轮 |
| C7 | CIG-inspired context | 仅适配关系状态及更新的上下文层，保留本框架原生提案/选择规则；明确不是原生 CIG | 必须的直接强对照 |

先做原生 C0 的证据移除/补回与粒度实验，详见深化设计；有证据作用的信号后，再做 C0/C2/C3/C6 策略探索。正式方法结论补齐 C1/C4/C5/C7。适配方法保存原论文机制、实现/提示差异、预算与失败案例，不能冒充原生论文结果。原生 CIG 还改变图驱动规划及候选组合选择，应另作系统级对照，不计入“仅替换上下文”的主效应。

普通 Summary 和 Retrieval 不能刻意省掉必要的可见输入或用明显不足的参数制造弱对照。Full Context 的“完整”是权限和原生访问能力，不等于允许无限 token；达到公平预算或窗口限制时如实记账，不能免费重试。

## 2. RSI Framework 验证轴

| ID | 框架 | 用途 | 优先级/现状 |
|---|---|---|---|
| R0 | HarnessFix | 首个成本审计与证据干预系统 | P0；工程接入及两轮评分完成，正式证据干预未做 |
| R1 | Meta-Harness | 以丰富历史文件访问为特征的核心确认框架 | P0；工程接入及两轮评分完成，正式上下文实验未做 |
| R2 | GEPA | 反思输入场景，主要在 reflective dataset 边界适配上下文层 | P1；旧 SWE 接入已有，新上下文实验未做 |
| R3 | RRSI | 在 Domain 的轨迹读取/渲染边界验证泛化 | P1；旧接入已有，新上下文实验未做 |
| R4/R5 | DGM / Harness² | 后续可选扩展 | P2，不在第一阶段铺开 |

同一框架中只改变上下文层，保留其核心候选选择、修复/进化、验证及接纳过程。尤其不移除 HarnessFix 必需诊断和回归验证来换取低成本。跨框架主要看各自 C6 相对 C0/强上下文对照的收益，不能仅按异构框架最终分数推断上下文方法优劣。

## 3. 固定轨迹的配对实验

每个实验单元是一份冻结快照，包含 H₀/当前候选源码、允许读取的轨迹、候选历史、可公开的开发反馈、历史截止点和剩余预算。不同上下文组共享同一份原始资产和信息权限，但输出的表示与实际读取量可以不同。

1. 在揭示任何新候选结果前，冻结快照和组别配置。
2. 每组从独立会话开始，组织上下文并在相同提案预算下生成候选；组织器额外调用计入本组。
3. 不读取其他组的候选、诊断或评分，不检索历史截止点之后的信息。
4. 用相同环境与执行预算评测，按同一开发选择及回归规则决定保留或拒绝。
5. 提名后再评估独立测试集。研究者若查看测试结果来调整方法，该部分即转为开发记录，需另设确认数据。

原有 Mini50 已用于多轮工程与候选选择，只能作为开发/审计资产。新的 split 清单需标明反馈、选择和最终测试用途，审计仓库与任务近重复；不能在同一 50 题中重新随机拆出“从未见过”的结果。

共享快照对照只支持该起点下的表示效果；之后再跑完整 RSI，观察上下文随历代候选增长时的净收益。重复快照、下游任务和独立搜索属于不同统计层级，不混作独立样本。

## 4. 双预算与完整成本

| 比较 | 固定什么 | 主要回答 |
|---|---|---|
| 固定候选/评测预算 | 相同候选上限、开发评测与每题执行预算 | 产生同等质量候选能否少花净 token |
| 固定总 token 预算 | 搜索阶段共同总额，包含组织器、优化器及开发/选择执行；每题执行限制仍相同 | 同等资源能否获得更好 Harness |

两种预算方案分别运行并报告；固定 token 组不额外强制生成相同候选数，实际候选与评测量仍须列出。框架原有成本正则项和接纳公式在组内保持一致，不为了新方法额外调权。

共享初始历史采集和最终封存测试的边界/数量对各组一致，费用单列并纳入全流程成本。若另做只限制优化器＋组织器的搜索模型 token 对照，明确标为补充预算，不能冒充全系统等总 token；更多候选引出的执行开销也要计入。

成本按请求 ID 分为互斥集合：原生优化阶段、额外上下文处理、历史采集、任务/选择/最终评测。总 token 为这些实际请求的无重复和。索引与摘要生成若原本已在框架中发生，应归入原生阶段；同一请求不能再加一次组织器成本。

同时记录输入/输出 token、缓存命中、模型型号、API/工具时间、调用失败与预留额度。重复发送的历史属于实际输入成本；token 归因可用分块标记/分词估计，但 API usage 是总量依据，归因误差需单列。缓存折扣及真实费用与原始 token 分开报告。

失败请求若缺失 usage，记录为未知并保留原始请求及预留额度，不把实际 token 的缺失填写为“已确认免费”。

## 5. 指标和选择规则

- 主指标：优化器实际 token、上下文额外成本、有效 Harness 修改率、独立测试 Resolve Rate。
- 有效修改率的分母包含全部已生成候选；合法、可执行、满足预注册开发收益/回归约束才计为有效。语法坏、无操作和被拒绝候选的成本不删除。
- 允许选择保留 H₀；接纳阈值、同分规则、验证次数和最终候选提名在开跑前冻结，不能看最终测试选最优版本。
- “保持质量”须定义非劣/可接受退化界限，结合配对区间判断；仅有不显著差异不等于保持效果。
- 报告成功新修复与回归、预算停止和基础设施无效；无效评分不记成零分，也不免费重复付费执行。
- 公开成本—性能曲线、独立搜索重复及不确定性，不仅报告平均压缩率。

## 6. 机制消融

在相同模型、原始历史和资源下，逐项去除修改问题条件化、源码锚点、前后状态、历史 diff/验证结果、成功/回归反例、按需展开。另设“普通检索＋相同输出长度”和“相同结构但不按当前决策选证据”对照。

去除信息是有意干预，效果只能说明所测场景中的作用；等长不保证等信息。查询生成、自动标注和额外修复提示不能成为未记账的教师帮助。对每种失败保留原始证据引用，审计选择性呈现或错误摘要。

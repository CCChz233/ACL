# 冻结模型的代码与终端 Agent：Baseline 方案

> 历史方案，不作为当前待办。2026-10-19 当前主线已替换为“面向 Harness 修改决策的证据高效上下文”，见 [研究故事](research_story.md) 与 [当前对照协议](harness_baselines.md)。以下保留 2026-10-13 的外部经验方案，旧组件比较/蒸馏故事同样已退出当前主线。

更新：2026-10-13。本文是待执行方案；没有已完成的 Agent 运行或方法结果。

## 当前问题

按当前决定，不进行 SFT、LoRA、RL，也不训练记忆选择器。固定 Solver 模型和执行工具，通过外部经验研究后续任务表现。

当前候选问题是：单独有用的经验组合后是否可能互相干扰，能否依据独立开发反馈选择更有效的经验组合？这是待验证假设。现有记忆选择和干扰研究已经构成相关工作，不能预先声称方法首创。

## 首轮对比

| 组 | 方法 | 目的 | 状态 |
|---|---|---|---|
| B0 | 固定 mini-swe-agent 执行循环，不使用跨任务记忆 | 测量模型与执行框架的基础能力 | 官方源码已下载；未安装、待接入 |
| B1 | 普通经验检索：BM25 和冻结 embedding 检索，分别比较 top-1/3/5 | 判断记忆收益及对检索器、条数的敏感性 | 待实现 |
| B2 | ReasoningBank：从成功与失败轨迹提炼并检索推理经验 | 对比已发表、有作者代码的自进化记忆方法 | 已核实作者源码，未下载、未复现 |
| Ours | 候选经验组合选择，可拒绝注入记忆 | 检验组合效用是否超过单条相关性或效用 | 待现象实验后设计 |

ReasoningBank 作者仓库包含 SWE-Bench 实现，基于 mini-swe-agent：[作者代码](https://github.com/google-research/reasoning-bank)。首先复现基本记忆版本；MaTTS 的额外并行/顺序采样作为独立设置计入成本，不能默认混入基本版本。

第二轮候选为 CMI（Causal Memory Intervention）：它通过干预比较候选记忆效用，已有作者实现，但原任务是对话记忆与合成任务。移植到代码/终端需要另做反馈设计，应明确称为 **CMI-adapted**，不能把移植结果称为原论文完整复现：[作者代码](https://github.com/Saksham4796/causal-memory-intervention)。移植前核对其实现、依赖与许可。

SEAL、Absolute Zero Reasoner 保留为文献和机制参考；本轮不复现其参数训练流程。

mini-swe-agent 官方源码已下载到 `repos/mini-swe-agent`，固定提交与归档哈希见 `docs/agent_sources.lock.json`。本地 Pro 还提供 `v2/tooling/host_mini_swe.py` 适配器。源码下载不等于依赖安装或运行通过；官方当前 v2 与 ReasoningBank 附带版本的接口与行为需要核对。mini-swe-agent 负责模型调用和工具执行，Harbor/benchmark harness 负责任务环境、重置与评分。

## 消融与现象检查

- top-1 对比 top-k：更多经验是否稳定更好？这也可以作为 B1 的条数配置。
- 等长度随机经验：区分经验内容与额外上下文本身的作用。
- 单条效用选择：比较组合选择是否超过只给候选经验逐条打分。
- 移除组合交互判断：保留相同候选、筛选反馈和预算，检验交互部分是否必要。

“干扰”实验应在开发集上比较无记忆、A、B、A+B，并用重复运行检验差异。单个案例中 A+B 失败不足以证明系统性干扰；额外上下文长度和挤占执行预算也可能导致下降。增加等长度控制并记录截断情况。

## 数据与公平比较

1. 分开经验获取集、方法开发集和封存测试集。代码审计仓库身份与任务近重复；终端审计来源、模板和内容。经验获取不等于模型训练。
2. 选择机制实验使用同一个冻结经验池，保持候选表示一致。ReasoningBank 的原生提炼实验另列：使用相同来源轨迹，但允许各方法产生自己的记忆表示；不能把固定池变体冒充完整 ReasoningBank。
3. 所有组固定模型版本、执行框架、工具、提示的公共部分、任务、初始环境和运行设置。独立运行不共享可变记忆状态。
4. 固定 Solver 执行预算，另做总成本约束。提炼、embedding、评分、验证、候选搜索和额外模型调用都计入成本；预算无法完全匹配时报告成功率—成本曲线。
5. 候选验证只能使用获取/开发阶段允许的反馈。最终任务的参考补丁、隐藏 verifier、答案和最终分数不提供给记忆选择模块。Agent 可以执行协议允许的仓库测试，但不能访问独立 grader 的隐藏反馈。
6. 在开发集确定 k、阈值、模型和预算，最终评测前冻结。静态记忆迁移与在线积累实验分开报告。

## 跑哪些任务

先用 1–3 个开发检查任务验收环境、重置、工具、评分与日志，再用约 20–30 个独立代码开发任务比较 B0/B1/B2。这是工程预试验，不能支撑论文结论。

Verified Mini 可用于开发检查，但 50 个任务属于 Verified；如果用于方法选择，后续未见 Verified 评测应排除这 50 个。独立经验获取任务尚未准备完成，不能把这些开发任务或最终测试答案直接写入经验库。

代码链路稳定后再接终端。正式评测沿用固定版本的 SWE-bench Pro V2、Terminal-Bench 4.0.0；Verified 与 Terminal-Bench 2.1 为参考，各自独立报告。遵守各自运行与评分协议，较短研究预算不得直接对照官方榜单。

## 记录与判断

记录每任务成功与否、工具步数、运行时长、模型调用、输入/输出 token、成本、基础设施故障、候选与注入的经验 ID。保留可复查轨迹与版本信息。

正式结果至少做三次独立运行，以任务为单位计算配对差值和置信区间；重复轨迹不当作独立任务。代码与终端不合并成单个总分。

第一阶段回答“经验有无收益、强基线表现如何”；第二阶段回答“组合选择是否带来额外收益”。若进一步主张持续自改进，还需按独立任务流积累经验，并在固定检查点评测封存任务与旧能力保留；静态检索变好本身不足以证明 RSI。

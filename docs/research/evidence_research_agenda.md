# 深化研究：Harness 修改决策的证据需求与获取策略

更新：2026-10-20。对应用户确定继续深化“优化器需要哪些轨迹、源码和修改历史”的方向。本文细化 [当前研究故事](research_story.md)，不另立第二条主线。所有方法和新实验均为计划；本次没有启动付费模型调用或新一轮搜索。

## 1. 收窄后的核心问题

> 在固定模型和 RSI 核心协议下，哪些证据、以什么粒度、在什么决策时点影响 Harness 修改的结果？能否根据这些需求获取证据，在完整成本口径下改善后续 Harness 的质量与成本关系？

第一阶段优先研究证据的作用，再设计读取策略。不能预设长上下文一定浪费，也不能预设摘要一定丢失重要信息。“读取过”“模型引用过”“事后看来有关”都不等于证据实际改善了修改。

暂定工作标题：**What Evidence Does Harness Self-Improvement Need?**。EAEC 仅保留为已有候选实现的代号，不先把一组常见组件包装成已成立的新方法。

## 3. 三个递进研究问题

| 研究问题 | 具体检验 | 允许得出的结论 |
|---|---|---|
| RQ1：证据在哪里产生价值？ | 在相同历史和父版本上移除某类证据，观察实际候选与评分；再做定向补回 | 在所测模型、快照、访问约束和预算下，该证据的可用性影响了结果 |
| RQ2：需求是否随决策与粒度变化？ | 比较摘要、局部原始窗口、完整原始材料；按原生阶段/决策类型分层 | 哪些场景适合摘要，哪些需要展开，以及是否存在差异 |
| RQ3：需求能否转化为有效策略？ | 固定策略后，对比原生访问、检索和强方法；完整计入组织及评测成本 | 策略在测试分布上是否改善质量—成本关系，及失效范围 |

“必要”不是所有模型和所有任务中的逻辑必要；不声称找到全局最小充分证据集。历史相关性、模型自述和图中连线也不能单独证明 Harness 故障的真实因果机制。

## 4. 实验单元与信息边界

主单元是一份生成新候选前的冻结快照：父 Harness、当时可见历史、源码与 diff、允许反馈、框架状态、时间截止点、模型配置及剩余预算。每份输入有文件哈希及来源引用。

- 第一套系统沿用 HarnessFix，先完成其成本与上下文替换边界审计；Meta-Harness 是必须的第二套核心确认，不以五框架大排名替代方法研究。
- 固定 DeepSeek Flash、mini-SWE-agent、编辑范围、原生提案/修复过程、父版本选择、验证和接纳规则；不训练模型权重。
- 观察原有阶段与调用点，记录诊断、方案、实现和验证相关决策；不能为了方法组增加免费专家方案，或强迫额外阶段后仍称核心流程完全相同。
- 普通方法对照共享相同底层信息权限。消融组的证据可用性变化是显式干预，单独标注，不能偷偷从另一个文件或工具恢复被移除内容。
- 被删内容若已被前序对话或摘要吸收，须在污染之前的快照重启；不能在同一会话里仅删除文件后当作“没看过”。
- 快照截止点之后的候选、评分、参考修复和事后诊断不得进入输入。已看未来结果的人工标注只用于审计或明确标注的回顾性分析。
- 两个相邻快照不是两次独立搜索；下游题目也不是独立的优化器重复。保留 lineage、snapshot、replicate、task 四级标识。

现有 Mini50 和十题都已被开发与选例使用。可用于探索、调试和开发检验，不能重新随机切分后声称全新未见。确认实验需另行冻结数据，检查任务与仓库的重叠及适用范围。

## 5. 先做证据干预，不急着发明新组织器

### 5.1 成本与证据清单

把原生请求按阶段登记；将证据读取关联到轨迹片段、源码、历史 diff/评分与其他材料。记录重复读取、截断、缓存和实际 usage。API 总 token 是精确口径；按证据类型分摊属于估计，需注明分词方法和误差。读得多不等于没有价值。

### 5.2 候选证据类别

| 类别 | 内容 | 待验证假设 |
|---|---|---|
| 当前行为证据 | 失败前状态、动作、观察、后果和相邻窗口 | 错误摘要有时不足以定位发生过程 |
| 源码证据 | 当前版本的实现、调用关系、接口约定 | 某些修改需要实现级信息，而非只有轨迹 |
| 修改历史 | 当时已有的 diff、评测和拒绝/保留记录 | 可减少重试已失败改动，但也可能形成错误锚定 |
| 对照证据 | 当时已有的成功轨迹、修复收益与回归案例 | 可能帮助限定修改作用范围，也可能增加干扰 |

这些都是假设；不以 Meta-Harness 的单个提交异常作为全部机制的代表。

### 5.3 移除—补回—粒度对照

1. 从含有目标证据且没有未来信息的同一快照，建立原生完整访问条件。
2. 每次移除一种证据及其派生摘要，保留其余信息和相同候选生成/评测协议。
3. 在独立会话中补回同一类证据，比较额外信息可用性是否恢复候选质量；多次重复，不把单次翻转当作稳健效应。
4. 对出现信号的类别比较摘要、局部原始窗口、完整材料；以“相近呈现预算但不同相关性/选择规则”的对照辅助解释长度影响，承认等长不等信息。
5. 同步检查预算耗尽、访问失败、接口错误及其他工程原因。交付失败、真实解题失败和基础设施失败分开登记。

原生可访问、移除、补回是三个独立条件，不是在一条对话里不断增加信息。若补回项由研究者根据新候选的未来结果挑选，只能作为回顾性分析；可部署策略必须只用决策当时的信息选取证据。

先审计全部候选快照，再按预先声明的覆盖规则选探索子集；覆盖成功、失败及历史丰富程度，不只挑最支持故事的案例。不立即进行全部证据类别的组合穷举。

## 6. 有信号后再实现读取策略

候选策略只控制下一次读取的证据类型、粒度和数量，保留原生修改与评测规则。起步可用透明固定规则；之后才考虑学习策略。当前未证明需要新模型或额外 Agent。

例如：先呈现来源索引和已有评分；需要检查某个接口时展开对应源码；当前解释与历史结果矛盾时再展开相关旧 diff 和原始轨迹。**这些行为本身已有先例，必须用实验说明相对现有自主检索和结构化历史方法的增量。**

展开触发因素可以来自原生工具查询、待核实断言和可观察证据缺口；模型说“我不确定”不能单独充当可靠性指标。不新增一套停止或父候选选择策略混入上下文主比较。

对照要求：

- 原生完整历史访问、通用摘要、普通检索保留相同合法源材料和工具能力，不制造弱基线。
- ContextEvolve-adapted 保留状态、方向和样例选择；记录与原论文的适配差异。
- CIG-inspired context 仅移植其关系状态的上下文版本，不能称作原生 CIG。原生 CIG 涉及规划和候选组合选择，应另作系统级对照，明确改变了搜索流程。
- ACON-adapted 作为学习式压缩扩展；若主要价值仅等于更好的压缩，主张应相应收窄。

## 7. 指标、预算与统计

| 层级 | 指标 | 限制 |
|---|---|---|
| 证据 | 读取来源/粒度、重复率、访问或摘要错误、实际 token | 引用或命中率不是修改质量 |
| 决策 | 修改位置/方案改变、历史失败重试、证据支持情况 | 属于中间机制指标，需可追溯规则；模型评分不能替代真实执行 |
| 候选交付 | 合法修改率、可运行率、无操作率 | “能运行”与“提高解题率”分开 |
| 候选质量 | 配对新修复/回归、开发/独立测试 Resolve Rate | 相对实际父版本；报告原始候选和保留版本 |
| 效率 | 固定候选及评测规模的净成本；固定搜索总预算的质量 | 不只报摘要长度或 proposer token |

搜索总成本含组织器、查询规划、原生优化、失败请求、开发/选择评测；共同初始历史采集及最终封存测试保持一致并单列全流程成本。组织器缓存分别报告首次构建和摊销；真实费用、缓存计费和原始 token 不混写。

先用探索试验估计成本与波动，再冻结正式样本量、独立搜索重复、质量容忍界限及比较方案。十题单次结果的最小分辨率是 1/10，不能据此声称保持几个百分点以内的质量。不显著不等于等效。

重复生成使用独立会话，记录 replicate ID 和供应商实际支持的随机配置；相同 seed 不保证 API 输出一一配对。统计按历史/搜索谱系分组，报告逐快照与跨独立搜索的结果，不把共享历史多次采样当成大量独立样本。

## 8. 阶段、交付与继续条件

| 阶段 | 交付物 | 判断下一步 |
|---|---|---|
| A：零 API 审计 | 相关工作机制矩阵、原生调用边界、可用快照清单、账本与证据字段规范 | 输入来源和截止点可信，清楚哪些干预可实现 |
| B：小规模证据干预 | 相同快照的原生/移除/补回候选及独立会话重复，统一开发评测 | 证据影响不完全由工程失败、长度或一次随机结果解释 |
| C：固定读取策略 | 原生检索与强方法对照、机制消融、双预算结果 | 组织开销计入后仍有可复现收益或明确适用边界 |
| D：完整 RSI 与确认 | 策略冻结，历史增长、多轮与独立数据；Meta-Harness 确认 | 可支持何种范围的泛化，是否需要缩小主张 |

阶段 A 先做，不因方向确定就自动启动五框架多轮搜索。新付费实验的快照数、重复数、任务执行数及费用上限在审计后形成具体配置；历史预算不自动迁移。先记录每组候选/评测数量，再计算总任务执行量，不把“十道题”误当作整个实验只有十次执行。

若证据删除基本不影响结果，应先检查条件是否真的改变信息、统计波动和任务是否需要该类证据；若仍无信号，应报告弱依赖或缩小到合适场景。若原生自主读取已经达到相同成本—质量前沿，则不硬做组织器。若收益只来自更短输入，则改为压缩贡献，不声称理解了证据需求。

## 9. 现有结果能支持什么

五框架高预算两轮结果见 [最终汇总](../../experiments/runs/full10-highbudget-completion-v1/report.md)。它们提供历史和候选来源，不是上下文策略随机对照，不能证明某框架得分更高是因为证据组织更好。

[同轮编辑核验](../../reports/exports/within-round-audit-2026-10-20/findings.md) 确认 Meta-Harness 第一轮晚期修改破坏提交协议；两份恢复补丁通过官方测试。它支持补全运行协议检查，不证明中间 Harness 自由运行成绩先涨后跌，也不将“防止改坏”重新升级为主线。

## 10. 当前可写的贡献目标

1. 在受控输入干预下，分析特定模型与协议中不同证据对修改决策及真实候选质量的条件作用。
2. 根据实验证据设计可追溯的分粒度读取策略，并解释它何时优于原生访问、通用检索和相关强方法。
3. 在完整成本和独立确认条件下报告质量—成本关系，公开无效条件和工程错误对结论的影响。

以上是可否证的目标，不是已取得的结论。第一项本身若已有充分先例，也必须按具体实验区别继续收窄。
